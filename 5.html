1. VME Manager アプライアンスのバックアップ ＆ リストア手順

UI Path: Administration > Settings > Backups
運用タスク 設定・実行手順 重要注意点・ハマりポイント（失敗例と対策）
DBバックアップ
(自動スケジュール)		 Administration > Settings > Backups で BACKUP APPLIANCE トグルを有効化。
スケジュール（日次等）と保存先ストレージプロバイダーを指定。
Storage Provider Warning デフォルトの保存先はローカル（/var/opt/morpheus/morpheus-ui/）です。外部の NFS または S3（Storage Bucket）へ変更しないと、アプライアンス破損時にバックアップごと喪失します。またローカル容量枯渇でUI停止の原因になります。
アプライアンスDB
手動リストア手順
# 1. UI サービスを停止
sudo morpheus-ctl stop morpheus-ui

# 2. DBパスワードを secrets ファイルから確認
sudo grep mysql /etc/morpheus/morpheus-secrets.json

# 3. 組み込み MySQL バイナリでバックアップ SQL を流し込み
/opt/morpheus/embedded/mysql/bin/mysql -u morpheus -h 127.0.0.1 morpheus -p < /tmp/morpheus_backup.sql

# 4. UI サービスを再開
sudo morpheus-ctl start morpheus-ui
Command Clarification morpheus-ctl backup という単独CLIコマンドは存在しません。リストア時は必ず組み込みMySQLバイナリ（/opt/morpheus/embedded/mysql/bin/mysql）を使用して流し込みます。

2. HVMホストのメンテナンス手順（ノード退避・パッチ適用・復旧）

UI Path: Infrastructure > Clusters > [対象クラスタ] > Hosts > [対象ホスト]
ステップ 操作手順 / CLI コマンド 仕様・確認ポイント ＆ 注意点
Step 1: ホスト退避
(Maintenance Mode)		 対象ホスト詳細画面右上:
ACTIONS > Enter Maintenance Mode
Pinned VM Block Hazard 実行すると稼働中VMが他ノードへ自動ライブ退避されますが、特定ホストにピン留め（Affinity / Pinned）されたVMやローカルリソースを占有するVMがある場合、メンテナンス移行がブロックされます。事前に手動退避または停止が必要です。
Step 2: ホストOSパッチ適用
# 公式標準コマンド（dist-upgrade は非推奨）
sudo apt update && sudo apt upgrade -y

# 閉域網環境：HPEアップグレードバンドル適用時
# hvm-upgrade-bundle.zip を解凍しローカルリポジトリ登録

sudo reboot
カーネルやKVM関連のアップデートが完了後、ノードを再起動。
Step 3: メンテナンス解除 再起動完了後、対象ホスト詳細画面右上:
ACTIONS > Exit Maintenance Mode 		ノードがクラスタに復帰し、Dynamic Placement（DRS）の自動配置対象に戻ります。

3. VMバックアップ ＆ スナップショットの重要制限（即死・トラブル回避）

Critical: Shared Disks Excluded from Snapshots 共有ディスク（Shared vDisk）はスナップショット対象外：
HPE公式ドキュメントに明記されている通り、GFS2 Clustered Datastore 上の「Shared LUN / 共有ディスク」はスナップショット取得対象から自動的に除外（Excluded）されます。クラスタDB（Oracle RAC、MSFC等）のVMバックアップ設計時は、ディスクスナップショットではなくエージェント型（ゲスト内部）バックアップを併用する必要があります。
機能・対象 仕様・制限事項 トラブルシュート・回避策
マネージャー復元後の
孤立スナップショット		 VME Manager を過去のバックアップからリストアした場合、バックアップ取得後〜リストアまでの間に作成された VM スナップショットは、Morpheus UI 上から消失（表示不可）します。 UIには表示されませんが、ハイパーバイザー（KVM）およびストレージ上にはスナップショット差分ファイルが残存（孤立）しています。ストレージ容量圧迫やロック競合を防ぐため、ホスト側 CLI（virsh snapshot-list / qemu-img）で手動確認・削除が必要です。
GFS2 スナップショット
長期保持の性能劣化		 GFS2 Clustered Datastore 上でスナップショットを多数作成・長期保持すると、DLMの分散ロック競合が増加し、VMのI/O遅延の原因になります。 スナップショットはパッチ適用等の短期検証用途に限定し、24〜48時間以内に削除する運用ルールを徹底してください。

4. リリースノート（v9.0.2 / Central）既知の制限 ＆ 注意点マップ

コンポーネント 事象・既知の制限事項 現場での回避策・対処法
Netplan インターフェース
動的追加の非反映		 クラスタ登録後にホスト側で /etc/netplan/ を書き換えて物理NICを追加しても、VME Manager UI 側に即時反映されない場合があります。 Infrastructure > Clusters > 対象クラスタ の ACTIONS > Refresh Cluster または Sync Clusters を実行してノード情報を再同期させてください。
VNC コンソール
WebSocket 遮断		 自己署名SSL証明書を使用している環境において、最新ブラウザ（Chrome / Edge 等）からVNCリモートコンソールを開こうとすると、WebSocket接続がセキュリティ警告でサイレント遮断される。 アプライアンスおよびHVMホストに正規の社内CA署名済みSSL証明書を適用するか、ブラウザ側でマネージャーURLおよびホストIPの証明書を例外許可（信頼）してください。
