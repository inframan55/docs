Phase 05 / Image & Provisioning

仮想イメージ準備（Linux/Windows）＆ プロビジョニングトラブルシュート Virtual Images, VirtIO, Sysprep Trap, Provisioning & Finalize Hang Fix

HVMクラスタ上で動作させるゲストOSイメージの事前仕込み要件（Cloud-Init / VirtIO / Sysprepの作法）と、 VM展開時のパラメータ設定、および「Finalize（99%）で永久スタックする障害」の調査・回避手順です。

1. 仮想イメージ登録（Library > Virtual Images）の必須フラグ

UI Path: Library > Virtual Images > + Add
設定項目・フラグ 設定値 / デフォルト 重要注意点・ハマりポイント（失敗例と対策）
Cloud-Init Enabled デフォルト: ON
Instant Provisioning Failure cloud-init 未導入イメージでの即時爆死： OSイメージ内に cloud-init パッケージが入っていないにもかかわらず、このフラグをONにしたまま展開すると即座にプロビジョニングが失敗します。自作イメージ等で未導入の場合は必ず明示的にOFFにしてください。
VirtIO Drivers Loaded? 手動チェック必須 KVMベースのHVM環境では必須フラグです。VirtIOドライバ（ストレージ/NW）を事前組み込みしたLinux/Windowsイメージでは、必ずチェックを入れて有効化してください。未設定の場合、IDE/SATA等の低速エミュレーションフォールバックや起動失敗の原因となります。
Operating System 対象OSを厳密に選択
OS Type Mismatch Hazard Windowsイメージの場合、必ず「Windows Server 2019/2022」等を指定すること。未指定のままにすると、Morpheusは自動的にLinuxプラットフォームと誤認し、ゲストカスタマイズ時にBashスクリプトを注入しようとしてエラーとなります。
Username / Password 事前登録（条件付き） Cloud-InitなしのLinuxや、Sysprep一般化なしのWindowsイメージを使用する場合、MorpheusがSSH/WinRMで初期通信するための「既存の管理者資格情報」をここで事前登録しておく必要があります。

2. Windows ゲストイメージ作成作法（Sysprep自動起動の即死トラップ回避）

Critical Sysprep Trap: Do Not Select Shutdown Sysprepで「/shutdown」を選択すると即死します：
CLIやGUIで /shutdown を指定してOSを落とすと、HVMハイパーバイザー側の電源検知機能が即座に「意図しない停止」と判定してVMを自動再起動してしまいます。その結果、再セットアップが走り、Sysprepの一般化（Generalize）状態が解除されてイメージ化に失敗します。
ステップ 実行コマンド / 操作内容 仕様・確認ポイント
Step 1: VirtIO ドライバ組込 新規インストール時に ATTACH VIRTIO DRIVERS を有効化。
OSインストール後、仮想CDドライブから virtio-win-guest-tools.exe を実行。 		ネットワーク（NetKVM）およびストレージ（viostor / vioscsi）ドライバを完全に適用。
Step 2: WinRM リモート管理有効化 管理者PowerShell / CMD で実行:
winrm quickconfig -q
sc config WinRM start= auto
# ファイアウォール許可 (Port 5985/5986)
netsh advfirewall firewall set rule name="Windows Remote Management (HTTP-In)" new enable=yes
VME Managerからの初期構成スクリプト受信用に必須。スタートアップの種類を「自動」に設定。
Step 3: 正しい Sysprep 実行 GUIのSysprep画面またはコマンドで実行:
# 重要: シャットダウンではなく「/quit」を指定！
C:\Windows\System32\Sysprep\sysprep.exe /generalize /oobe /quit
実行後、C:\Windows\System32\Sysprep\Sysprep_succeeded.tag が生成され、Sysprepプロセスが「正常終了」してプロンプトに戻ることを確認。
Step 4: UI から安全に停止 Morpheus UI の対象インスタンス画面:
ACTIONS > Stop Server 		OS側からシャットダウンせず、Morpheus UIから停止をかけることで自動再起動を防止。
Step 5: イメージ化とフラグ設定 停止後、ACTIONS > Import as Image を実行。
作成された Virtual Image の編集画面を開く。 		以下のフラグをONにする:
・SYSPREPPED/GENERALIZED IMAGE?
・VIRTIO DRIVERS LOADED?
・INSTALL AGENT?
※Username / Password 欄に値が入っている場合は空欄（削除）にする。

3. プロビジョニングトラブルシュート ＆ Finalize（99%）スタック対策

UI Path: Provisioning > Instances > [対象VM] > History / Logs

プロビジョニング進捗バーが「Finalize」のまま停止し、最終的に警告（!）付きで完了するトラブルの9割は、ゲストVMからVME Managerへの通信不通（コールバック失敗）です。

障害事象・フェーズ 根本原因（切り分けポイント） 対処手順・回避策
Finalize 永久スタック
(通信不通)		 ゲストVM内部から VME Manager の Appliance URL（例: https://vmemgr.example.com）へ ポート 443 / 80 で到達できていない。
  • デフォルトゲートウェイ／ルーティング未設定
  • DNS正引き／逆引き（PTR）解決の失敗
  • 物理ファイアウォールによる遮断
Quick Workaround エージェント機能（メトリクス収集やゲストスクリプト実行）が不要な場合、インスタンス展開ウィザードの Advanced Options で SKIP AGENT INSTALL にチェックを入れることでFinalize待機をバイパス可能。
Finalize 永久スタック
(認証・ポート遮断)		 初期通信プロトコルの遮断:
  • Linux: SSH（ポート 22）疎通不可またはパスワード/鍵不整合
  • Windows: WinRM（ポート 5985/5986）未起動またはFW遮断
 ゲストOS側でサービス状態を確認し、ポート開放および認証設定を見直す。
