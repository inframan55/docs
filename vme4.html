SECTION: 01_OVERVIEW_AND_LICENSING HPE MORPHEUS VM ESSENTIALS (VME)

製品位置づけ & ライセンス体系設計

HPE Morpheus VM Essentials (VME) は、VMware vSphere 代替を主目的に最適化されたエンタープライズKVM基盤。クラウド管理プラットフォーム（Morpheus Data）のオーケストレーション機能をコアに組み込み、シンプルな仮想マシン運用を実現する。

1. 課金メトリクスとライセンス構造

ライセンスモデル 課金単位・体系 技術的特性・留意点
Socket課金モデル 物理CPUソケット単位
(Per-Socket Licensing)		 近年の主要仮想化ベンダー（コア課金）と異なり、ソケット単位の明確な課金を採用。メニーコアCPU（AMD EPYC / Intel Xeon 6等）を採用したスケールアップ設計時に高いコスト対効果を発揮。
管理プレーン
(VME Manager)		 無償バンドル / 追加費用なし vCenterに相当する管理VMライセンスが基本パッケージに含まれる。管理インスタンス数による追加課金が発生しない。
契約形態 サブスクリプション (1年 / 3年 / 5年) HPE Pointnextによる24x7ハードウェア＋ソフトウェア統合サポートが含まれ、基盤OS（Ubuntu）およびKVM部分の障害も単一窓口で対応。

2. 対象ワークロードとユースケース

コアターゲット

  • vSphere移行: サブスクリプション高騰に伴う汎用VMware環境の脱却
  • Windows / Linux汎用基盤: 業務AP、DB、AD、ファイルサーバー等の標準的集約
  • エッジ・拠点展開: 3ノード等の最小構成クラスタでの標準化

Morpheus CMPへの拡張性

将来的にマルチクラウド管理やセルフサービスポータル、コンテナ（Kubernetes）連携が必要となった場合、上位エディション（Morpheus Enterprise等）へのスムーズな機能拡張が可能。

SECTION: 02_STACK_AND_HARDWARE PLATFORM ARCHITECTURE

稼働スタック・ハードウェア互換性要件

VMEはベアメタルOSの上に仮想化レイヤーを積むハイブリッド構成を採る。Linuxのハードウェア互換性（HCL）を継承しつつ、エンタープライズサーバーとの動作保証を確立している。

1. ソフトウェアスタック構成

レイヤー コンポーネント 技術仕様
Host OS Ubuntu Server 24.04 LTS / 22.04 LTS Linux Kernel 6.x系。Canonicalの長期サポート（LTS）ベース。
Hypervisor HVM Hypervisor (KVM + QEMU) Linux標準のKernel-based Virtual Machine。VirtIO準仮想化I/O。
Orchestrator VME Manager + HVM Agent RESTful APIベースのノード制御。クラスタリソースの自動検出と同期。
Cluster Engine Corosync + Pacemaker + DLM クォーラム判定、ノード死活監視、GFS2共有ディスク排他調停。

2. ハードウェアプラットフォーム要件

対応サーバー環境

  • HPE ProLiant: DL360 / DL380 (Gen10 / Gen10 Plus / Gen11)
  • CPU要件: Intel VT-x / AMD-V 必須（ネスト仮想化対応）
  • メモリ要件: ノードあたり最低32GB（推奨64GB以上、管理プレーン用リザーブ含む）

ストレージファブリック

  • FC SAN / iSCSI: HPE Alletra / Primera / 3PAR / Nimble Storage および他社製主要ストレージ
  • 共有プロトコル: GFS2クラスタマウント用ブロックボリューム
  • NAS: NFS v3/v4 (テンプレート/ISO用リポジトリ)
SECTION: 03_ECOSYSTEM_AND_BACKUP INTEGRATION & PROTECTION

エコシステム連携・バックアップ＆データ保護

仮想化基盤の切り替えで最大のリスクとなる「バックアップ」および「ディザスタリカバリ（DR）」についてのサードパーティ連携仕様。

1. データ保護ソリューションの適合マトリクス

保護ソリューション 連携方式 バックアップ/復旧特性
Veeam Backup & Replication 専用 VME Plug-In 連携 CBT（変更ブロック追跡）ライクな増分バックアップに対応。既存のVeeamリポジトリをそのまま維持しながら、vSphereからVMEへのリストア・切替が可能。
Zerto ジャーナルベース CDP レプリケーション 仮想マシンのブロック変更をリアルタイムに差分転送。数秒〜数分のRPO/RTOを実現し、移行時のカットオーバー停止時間を最小化。
スナップショット管理 QEMU / libvirt スナップショット VME ManagerからVMスナップショットの取得・復元・削除が可能。パッチ適用前の一時バックアップとして利用。

2. 運用監視・認証統合

ディレクトリサービス連携

Active Directory (LDAP/LDAPS) および SAML 2.0 / OAuth によるシングルサインオン（SSO）に対応。Active Directoryのグループを利用したロールベースアクセス制御（RBAC）をManager上で設定。

モニタリング & メトリクス

ホストおよびVMのCPU/メモリ/IOPS使用率をManagerでダッシュボード表示。Syslog転送による外部SIEM連携、SNMPトラップによる監視基盤連携を標準サポート。

SECTION: 04_DESIGN_CONSIDERATIONS ENGINEERING CHECKLIST

設計上の制約・インフラサイジング考慮事項

実環境導入におけるクラスタサイジング、ネットワークトポロジ、運用設計時の重要チェックポイント。

1. クラスタ規模・ネットワーク設計基準

項目 推奨仕様 / 制限 インフラ設計上の必須対策
最小クラスタ構成 3 ノード Corosyncのクォーラム維持およびGFS2のDLMスプリットブレイン防止のため、実本番環境は3台以上を必須とする（2ノード構成は非推奨）。
クラスタ心拍NW
(Corosync)		 RTT 2ms以下
レイヤ2直結推奨		 ストレージや業務VMのトラフィック輻輳に巻き込まれないよう、専用VLANまたは独立した物理NICポートへの割り当てが必須。
共有データストアNW
(iSCSI)		 10GbE / 25GbE 以上
Jumbo Frame (MTU 9000)		 GFS2によるファイルロックメタデータ通信と高I/Oが同一ファブリックを通るため、帯域確保とMultipath (MPIO) 設定が必須。
時刻同期 (NTP) Stratum精度の共通NTP ホスト間のクロックドリフトが数秒以上発生するとクラスタメンバシップが離脱するため、高精度な外部NTPへの同期が絶対条件。

2. VMware vSphereからの移行時チェックリスト

  • ゲストOS内部のクリーンアップ: VMware Toolsのアンインストールと、VirtIO（Red Hat VirtIO Drivers）の事前導入。
  • 仮想ディスクのフォーマット: VMDKからRAW / QCOW2への変換プロセス（Bulk Migrationツール利用時は自動化）。
  • 仮想NICのマッピング: vSphereの分散仮想スイッチ（dvPortGroup）から、VME側のOpen vSwitch（OvS）ブリッジへの再紐付け。
  • RAWデバイスマッピング (RDM): RDMディスクを利用しているVMは、iSCSIダイレクト接続等への構成変更が必要。
