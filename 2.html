Phase 01 / Setup

VME Manager 初期共通設定ガイド Administration > Settings

初回セットアップ完了後、クラスタ作成やVM展開を開始する前に管理者が確認・投入すべき共通基盤設定です。 通信不整合によるプロビジョニング停止や、ローカルディスク枯渇によるアプライアンス障害を未然に防ぎます。

1. Appliance Settings（アプライアンス基本設定）

Target: Administration > Settings > Appliance
設定項目 仕様・入力値 重要注意点・ハマりポイント（失敗例と対策）
Appliance URL エージェント自動インストールや通信で使用する既定URL
（例: https://vmemgr.example.com）
Protocol Restriction IPアドレス指定であっても、必ず https:// で記述すること（http:// は不可）。
  • 通信＆DNS（PTR）要件： 全HVMホストおよび展開される全VMから、ポート 443 / 80 で到達・正引きおよび逆引き（PTR）解決可能であること。導通がない場合、Agentのインストールが即座に失敗します。
  • 個別上書き： 特定のプライベートNW経由で通信させる場合は、Infrastructure > Clouds > Edit Cloud > Advanced Options の Alternate Appliance URL で個別上書き可能。
Internal Appliance URL (PXE) PXEブートサーバーが直接参照する内部URL NAT環境等で外部向けAppliance URLと異なる内部ルーティングが必要な場合のみ設定（未設定時は通常のAppliance URLを使用）。
API Allowed Origins CORSでAPIアクセスを許可するオリジン（ドメイン）リスト
Whitelist Caution 外部WebアプリからREST API呼び出しを行う際に設定。未入力時は全オリジン許可ですが、1件でも入力すると排他的ホワイトリストになります。

Max Option List Size REST API等で取得する動的オプションリストの最大件数（指定数値 × 1,000 件） 「1」と入力すると上限1,000件。巨大なペイロードによるアプライアンスのメモリ枯渇・パフォーマンス低下を防ぐための防壁です。

Phase 03 / Deploy & Cluster

ホストOS事前準備 ＆ HVMクラスタ・OVSネットワーク構築 Host CLI, Netplan YAML, Cluster Layout & OVS Bridge Setup

HVMクラスタを構成するためのUbuntu 24.04ホスト側の下ごしらえ（時刻同期・ファイアウォール・Netplan）と、 VME Manager GUIでのクラスタ登録およびOVS（Open vSwitch）ネットワークの構成手順です。

1. Ubuntu 24.04 ホスト側 事前準備（CLI手順）

項目 CLI コマンド ＆ 設定ファイル 重要注意点・ハマりポイント
時刻同期
(Timesyncd)
# 公式標準は systemd-timesyncd（chronyは競合防止のため非推奨）
sudo nano /etc/systemd/timesyncd.conf
[Time]
NTP=192.168.1.10 ntp.example.com

sudo systemctl restart systemd-timesyncd
timedatectl status
Standard NTP Service HPE HVM OS公式手順では systemd-timesyncd が明記されています。追加で chrony 等を入れると競合して時刻ズレを起こし、Corosyncクォーラムが分裂する原因になります。
名前解決 ＆ 逆引き
(/etc/hosts)
sudo nano /etc/hosts
# VME Managerおよび全HVMノードのIP/FQDNを記載
192.168.1.20 vmemgr.example.com vmemgr
192.168.1.21 hvm-node01.example.com hvm-node01
192.168.1.22 hvm-node02.example.com hvm-node02
192.168.1.23 hvm-node03.example.com hvm-node03
全ノード間で双方向の名前解決およびPTR（逆引き）解決ができること。名前解決が引けないとクラスタAgentの初期疎通でコケます。
SSH ＆ 管理権限
# 管理用ユーザー作成とパスワードなしsudo設定
sudo useradd -m -s /bin/bash morpheus
sudo usermod -aG sudo morpheus
echo "morpheus ALL=(ALL) NOPASSWD:ALL" | sudo tee /etc/sudoers.d/morpheus
sudo chmod 0440 /etc/sudoers.d/morpheus
VME ManagerがSSH経由でノードにKVM/OVSモジュールを導入するため、NOPASSWD:ALL が必須です。
ファイアウォール ＆
必須ポート開放
# 推奨：検証・内部クラスタ時はUFW無効化
sudo ufw disable

# 個別許可する場合の必須ポート一覧
sudo ufw allow 22/tcp # SSH
sudo ufw allow 80,443/tcp # HTTP/HTTPS
sudo ufw allow 7443/tcp # Hypervisor Console（必須）
sudo ufw allow 5404:5406/udp # Corosync（5404必須！）
sudo ufw allow 21064/tcp # dlmd (DLM ロック通信)
sudo ufw allow 2224/tcp # pcsd 通信
sudo ufw allow 3121,9929/tcp 9929/udp # クラスタ制御
sudo ufw allow 3260/tcp # iSCSI
sudo ufw allow 5900:5999/tcp # VNC Console
Deadly Port Lockout Corosyncのポートは 5404〜5406/UDP： 5404 が閉じているとノード間でクォーラムが組めません。また 7443/TCP（Hypervisor Console） が開いていないとManagerからホスト監視が通信エラーになります。

2. ネットワーク設計 ＆ Netplanコンフィグ（CLI）

VME Managerは /etc/netplan/ 配下に記述されていないインターフェースを自動検出できません。
クラスタに追加する前に、使用する物理NIC・BondをすべてNetplanに明記して netplan apply しておく必要があります。

# /etc/netplan/01-netcfg.yaml の設計例
network:
  version: 2
  renderer: networkd
  ethernets:
    # 管理用ポート（Management）
    eth0:
      addresses: [192.168.1.21/24]
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [192.168.1.10]
    # ストレージ用リンク1（Storage Link 1: MPIO用・非ルータブル・MTU 9000）
    eth1:
      addresses: [10.10.1.21/24]
      mtu: 9000
    # ストレージ用リンク2（Storage Link 2: 別サブネット・非ルータブル・MTU 9000）
    eth2:
      addresses: [10.10.2.21/24]
      mtu: 9000
    # VM通信/OVS用ポート（Compute: IPなしで活性化のみ）
    eth3:
      dhcp4: no
      dhcp6: no
Storage Subnet Separation Rule ストレージリンク（eth1 / eth2）は必ず別サブネットに分離すること： 同一サブネットを両方のストレージインターフェースに割り当てると、LinuxカーネルのARP応答問題によりマルチパスアクセス障害（片肺停止）を引き起こします。また、デフォルトゲートウェイは絶対に設定しないでください。
# 設定のテストと適用
sudo netplan generate
sudo netplan apply

4. OVSネットワーク構成（Bridge Domain ＆ Port Group）

UI Path: Infrastructure > Network > Routers および Networks
Strict Creation Order 作成手順の順序依存： 必ず最初に Routers タブで OVS Bridge Domain を作成し、その後に Networks タブで HVM Standard Network を作成して親Bridgeを紐付ける必要があります。順番が逆だとBridgeを選択できません。
ステップ ＆ メニュー 設定項目 設定内容 ＆ 動作仕様
Step 1: OVS Bridge Domain
(Routers サブタブ)		 + ADD > OVS Bridge Domain
・Name: br-vms 等
・Interface: eth3 		物理NICを仮想スイッチ（OVS Bridge）にバインドします。このBridgeがVM通信の土台（親ルーター）となります。
Step 2: HVM Standard Network
(Networks サブタブ)		 + ADD > HVM Standard Network
・Name: VLAN100-PG 等
・Bridge Router: br-vms を選択
・VLAN ID: 100（ネイティブVLAN）
・VLAN Trunks: トランク範囲（任意）
・IP Pool: 事前定義したIPAMプール 		VMのNICが接続する「ポートグループ」を作成します。ここでIP PoolやGateway、DNSを紐付けることで、VM作成時に固定IPが自動払い出しされます。
